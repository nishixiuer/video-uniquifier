# 素材到自动发布：原项目逻辑与桌面版迁移核对

核对日期：2026-10-26。原项目：`/Users/zhangyilan/www/media-share`。
本文件依据当前源码、模型、迁移及测试断言整理；没有连接原项目业务数据库，也没有执行真实授权、AI 请求或发布。

## 结论

原项目的核心链路是：**素材资料 → 批量生成任务 → 内容库 → 主页规则自动选稿 → 发布任务 → 发布结果回写**。
桌面版目前只迁移了部分文案生成、内容编辑、官方授权和发布能力，缺少素材资料模型和完整生成任务链路，不能称为完整业务迁移。

用户要求的目标链路是在这个基础上增加：**从源视频自动剪出成片，并与根据视频资料生成的 AI 推广文案组成帖子**。
原项目现有的视频分支直接引用已有视频，没有实现长视频自动剪片；原项目中的 FFmpeg 主要用于图片合成视频。必须区分原项目已有行为与本次需要补齐的行为。

## 1. 原项目真实业务

### 素材管理

- `Enterprise → Product → ProductMedia`：企业、产品资料、图片/视频文件分层管理。
- Product 保存名称、文字介绍、分类、来源地址、启停状态等；ProductMedia 保存文件地址、类型、顺序、来源和视频使用标记。
- “生成内容”的入口位于产品记录上，生成任务天然知道素材属于哪份资料，不要求每次重新输入介绍。
- 分类名称会自动加入生成内容的标签。
- 视频生成前检查已使用标记、已有内容引用及其他生成项的预占；失败会释放生成预占。

依据：[Product.php](/Users/zhangyilan/www/media-share/app/Models/Product.php:15)、[ProductMedia.php](/Users/zhangyilan/www/media-share/app/Models/ProductMedia.php:29)、[生成服务](/Users/zhangyilan/www/media-share/app/Services/ContentGenerationService.php:333)。

### 批量生成

每个批次以一个 Product 为来源，选择语种、提示词、AI 配置、标签和审核状态。批次保存配置快照，再拆成独立生成项交给后台队列。

| 原项目模式   | 实际执行                                                                           |
| ------------ | ---------------------------------------------------------------------------------- |
| 图片内容     | 指定数量；每条随机选图片，条内不重复，条间允许重复；可选择把图片发给 AI 做视觉输入 |
| 视频内容     | 为全部尚未使用的视频各生成一条内容；每条绑定一个已有视频，视频全局只消费一次       |
| 图片合成视频 | 随机选图，通过 FFmpeg 合成竖屏视频，配置停留时长、过渡和可选背景音乐               |

AI 输入包括产品名称、介绍、价格、企业、语种及素材信息。视频模式把视频链接写进文字上下文，不代表 AI 一定读取或理解了视频画面；没有视频转写或剧情识别流程。

生成项成功后才创建 Content，关联媒体、标签和来源资料。每项保存状态、错误、关联内容及时间；支持部分成功、逐项重试和整批重试失败项。审核状态可在创建批次时选择，默认未审核。

依据：[生成表单](/Users/zhangyilan/www/media-share/app/Admin/Forms/GenerateContentForm.php:89)、[批次创建](/Users/zhangyilan/www/media-share/app/Services/ContentGenerationService.php:148)、[AI 上下文](/Users/zhangyilan/www/media-share/app/Services/ContentGenerationService.php:316)、[AI 请求](/Users/zhangyilan/www/media-share/app/Services/AiContentGenerator.php:29)、[后台生成](/Users/zhangyilan/www/media-share/app/Jobs/GenerateContentItemJob.php:37)。

### 内容库

- Content 是可发布的内容成品：文案、图片或单个视频、来源产品、企业、语种、标签、审核状态、发布状态。
- 可以预览、编辑和审核；可以按来源、标签、语种、状态、发布主页等筛选。
- 发布任务独立保存；内容库能显示是否已排队、发布状态及发布结果。
- 手动创建是补充入口，素材生成才是批量生产的业务入口。

依据：[Content.php](/Users/zhangyilan/www/media-share/app/Models/Content.php:29)、[内容管理](/Users/zhangyilan/www/media-share/app/Admin/Controllers/ContentController.php:32)。

### 账号、主页与自动发布

授权账号关联 Facebook 主页，规则实际挂在主页与授权通道的关联记录上，发布目标是主页。现有调度不是把所有账号与所有帖子做笛卡尔组合。

每次扫描按以下顺序判断：

1. 全局发布开关开启，主页、授权通道和账号均启用且连接有效。
2. 当前时间在发布窗口内，未超过滚动 24 小时额度，并满足距离上次成功/已预占任务的间隔。
3. 主页配置了标签；选出命中任一标签、已审核、未发布、从未被发布任务占用的最早内容。
4. 内容的来源产品及企业也必须启用。
5. 锁定内容并创建唯一发布任务，防止多个主页抢到同一条内容。
6. 发布任务执行，记录成功结果或按失败策略重试；发布成功回写内容状态和远端链接。

原项目默认规则为每天 5 条、间隔 1 小时、全天窗口；界面要求结束时间晚于开始时间。额度为滚动 24 小时，0 表示无限制。定时入口是 `facebook:publish-scan` 命令，实际触发频率由运行部署决定。

依据：[调度器](/Users/zhangyilan/www/media-share/app/Services/FacebookPublishScheduler.php:33)、[内容筛选及预占](/Users/zhangyilan/www/media-share/app/Services/FacebookPublishScheduler.php:106)、[额度及间隔](/Users/zhangyilan/www/media-share/app/Services/FacebookPublishScheduler.php:144)、[发布任务](/Users/zhangyilan/www/media-share/app/Jobs/PublishFacebookContentJob.php:45)、[调度测试](/Users/zhangyilan/www/media-share/tests/Feature/FacebookPublishSchedulingTest.php:50)。

## 3. 按用户目标组织桌面版

主链路：

```text
素材库：源视频 + 名称/剧情介绍/推广资料 + 分类标签
  → 批量制作：选择素材、剪片规则、处理配置、AI 配置/提示词、语种
  → 后台生成项：制作成片 + 生成推广文案
  → 内容库：成片与文案配对、预览/参数对比/质量报告、审核
  → 自动发布：授权账号下的主页按规则匹配内容
  → 发布任务：执行、失败处理、远端结果回写
```

源视频可以产生多个不同片段；因此不能把原项目“一个已制作视频只消费一次”的规则直接套在长源视频上。建议分开记录源视频、片段区间、生成成片及发布占用，防止重复生成同一项、重复入库和重复发布。

剪片应是明确可配置的程序规则，例如片段时长、数量、选段/分段方式和处理参数；不能把“AI 生成文案”写成“AI 自动理解并剪辑剧情”。现有 Python 引擎提供裁切和处理基础，仍需补齐批量选段规划与帖子生成的任务编排。

生成任务须在重启后保留状态。视频制作或 AI 失败时，内容不能伪装成可发布成品；重试应复用已成功阶段。成片沿用已有内置视频对比、参数对比及质量报告入口。

建议页面职责：

| 页面       | 核心职责                                                           |
| ---------- | ------------------------------------------------------------------ |
| 素材库     | 导入视频、维护关联资料、分类/标签/启停、发起批量制作               |
| 批量制作   | 选择制作规则、预览生成计划、后台批次进度、失败项重试               |
| 内容库     | 查看成片与文案、审核、追溯来源、查看处理与发布状态                 |
| 账号与主页 | 官方授权、连接状态、主页启停及选稿/频率规则                        |
| 发布任务   | 查看排队与执行记录、失败原因、重试和发布结果                       |
| 服务配置   | Meta 应用、AI 接口、提示词等可复用配置                             |
| 高级工具   | 保留已有独立视频处理、诊断、实验、指纹索引入口，避免占据业务主导航 |

本地模板和手动编辑可作为补充功能；企业/商品价格等电商字段不应强制搬进短剧生产表单。Zernio、云对象存储、Laravel/MySQL/Redis、互动回复及运营统计不是完成本机官方发布主链路的前置依赖。

## 4. 实施优先级与验收

P0：素材资料与媒体持久化 → 可恢复的生成批次 → 自动剪片接入现有 Python 引擎 → 逐素材 AI 文案 → 成片/文案统一入内容库 → 审核与标签/启停条件 → 主页自动选稿和发布结果回写。

P1：更细的素材和内容筛选、批量操作、多配置/提示词管理体验、配图与图片合成视频等扩展路径。保留已完成的授权加密、官方上传、内置播放、参数对比和质量报告能力。

关键自动化验收：

- 从业务素材库发起任务，自动生成指定成片和对应文案，内容能追溯源视频、区间、资料和批次。
- AI 上下文与所选素材一致；配置/资料变化不篡改已创建任务的快照。
- 部分成功、逐项失败、取消和重启恢复有独立状态，失败重试不重复制作/入库。
- 未审核、未制作成功、已停用来源或已占用内容不会被自动选稿。
- 两个主页同时命中同一条内容时，只产生一次占用；时间窗、滚动额度和间隔规则均生效。
- 内容库能查看成片、内置原片/成片对比、参数与质量报告，以及最终发布状态。
- 测试模拟 AI/Graph API，真实 FFmpeg 测试使用临时素材，不产生真实发帖。
